## Findings and reasoning

No new exploitable authorization, tenant, cache-disclosure, or payment boundary defect was found in the reviewed diff.

1. **URL selection does not confer authority.** Sidebar derives active content only from the current user's permitted section list. Restricted Payments, fees alias, workforce and platform URLs resolve to Profile. Stripe and QuickBooks callback query strings select the Payments workspace only if it is permitted. The existing independent Payments versus Taxes & Fees component guards remain in force. Callback parameters trigger presentation/status refresh; they do not themselves invoke connect/disconnect/save. Backend provider mutation authorization and scoped step-up headers are unchanged.
2. **Restricted Fleet config no longer reads or exposes the protected form.** Both tax settings and Fleet company option queries are disabled without Taxes & Fees permission. The denial branch precedes pending/error/summary/editor branches. Cached tax data or a late successful response after local grant removal cannot render the summary or editor. An already-unlocked, dirty editor also disappears immediately. A server Axios 403 suppresses cached config and Unlock even if the local permission still says authorized. An ordinary network error exposes an explicit read failure/Retry, not empty configuration.
3. **Overview access remains an existing separate contract.** `/fleet/settings` and `/fleet/board` remain enabled for permitted Fleet viewers, guarded server-side by `require_fleet_access`; board/settings/customer queries remain tenant-scoped. Restricted configuration permission does not imply denial of Fleet Overview. `/fleet/companies` is more conservatively gated by the client for the config editor; server Fleet authorization is unchanged.
4. **Server is still the write boundary.** Current backend `admin.py` GET and PUT tax settings both use `require_permission("taxes_fees")`. `get_current_user` loads the current database User before `require_permission` examines its current permissions; local UI grants/password unlock do not authorize a save. Tenant is selected by authenticated user tenant, and default authority validation requires that same tenant and Fleet-enabled company. The patch does not change these rules or widen input fields.
5. **Session cache isolation remains intact.** Query keys are shared within a session, but actual `SessionQueryProvider` replaces the client on authenticated identity/tenant/role/session changes and clears the detached client. Independent probes using this real provider confirmed cached configuration and delayed old-tenant responses do not show in a replacement owner's tenant. A same-session Taxes & Fees permission change is handled by the immediate Fleet render/query guard, even though that permission alone is not part of the provider key.
