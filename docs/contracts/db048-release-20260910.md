## Deployment ordering and rollback

The API has a migration pre-deploy command; the worker does not. Therefore do
not rely on simultaneous auto-deploy ordering. After final CI/gates, retain a
private production backup, execute the exact candidate's additive migrations
and schema preflight as a one-shot step, verify head139 and old-service health,
then merge to trigger API/worker deployment. No payment backfill is automatic.

Keep the four gates off throughout. On problems, stop new attempts first and
retain schema/audit history. Do not downgrade financial tables or use an older
build lacking financial guards if new attempts have appeared. Revert via a
reviewed PR; direct main pushes are prohibited. Provider records are not repaired
or deleted as part of rollback.
