# DB149 invoice payment presentation — preview only
Owner Backend & Integrations; existing read-only contracts, no schema or payment mutations.

Acceptance: paid, unpaid, partial, cash, pending, overdue and cancelled copies clearly distinguish issued invoice total from verified current balance. Native settlement uses principal_total minus confirmed_principal (pending never deducted). Confirmed includes credit applications, so label payments / credits applied; do not claim cash received. Optional future card fees remain separately disclosed. Legacy completed payments use net verified amounts only when interpretable; refunded/inconsistent evidence returns unknown. Paid status without tender evidence may establish settled balance but never fabricate amount received. CashReceipt remains source of cash receipt total. Every query scoped invoice+tenant, deleted evidence excluded. Shared summary serialized to guest/staff detail, all PDF generators and newly generated invoice mail; old mail/downloads remain historical. Unit/DB negative/isolation tests; parent independent QA before deployment; user preview approval required.
